# 콘텐츠와 엔진 배포 분리

## 현재 계약

트레이너·전투·CVES·NPC 프리셋·퀘스트·월드·서식지·던전·지도·리그·경제·
스타터·가챠 데이터와 주요 UI 자산은 외부 콘텐츠 번들로 배포한다.
게임 모듈 8개와 건축 편집 모듈 2개는 외부 콘텐츠를 사용한다. 모든 모드의
JAR에서는 `data/`, `assets/`, `battle-ai/`, `pack.mcmeta`를 제외한다.
공통 `cobbleventure-content-runtime` 모듈이 콘텐츠 로딩을 담당한다.

```bat
build.bat content
build.bat content en_us
```

`generate`도 같은 명령의 별칭이다. 웹 편집기의 기존 생성 명령도 이 경로를
사용한다. 이 명령은 Java/Gradle 빌드나 엔진 JAR 설치를 실행하지 않는다.
트레이너 및 CVES 검증·컴파일과 NPC·NBT 변환은 여전히 필요하다.

산출물:

- `dist/cobbleventure-content-<버전>.zip`: 게임 디렉터리에 설치하는 콘텐츠 배포본
- `pack/overrides/development-placeholder/config/cobbleventure/content/`:
  개발 실행과 전체 팩 패키징에서 사용하는 콘텐츠
- `config/easy_npc/skin/`: EasyNPC가 별도 파일로 요구하는 스킨. ZIP에 함께 포함

번들 루트에는 `data/`, `assets/`, `pack.mcmeta`, `content-manifest.json`이 있다.
현재 `engine_contract`는 **2**다. manifest의 `engine_contract`는 엔진과의 호환 계약이며 `sha256`은 파일 목록과
각 파일 해시로 계산한 콘텐츠 식별자다. 서로 다른 파일을 같은 경로로 합치는
것은 오류로 처리하고, Minecraft 태그만 `replace` 규칙에 맞춰 병합한다.

## 설치와 적용

계약 2로 최초 전환할 때는 공통 런타임을 포함한 모든 엔진 JAR과 콘텐츠를 함께 갱신한다. 이후 해당 콘텐츠의
수정에는 콘텐츠 번들만 다시 생성하면 된다. `build.bat pack`은 전체 엔진과
콘텐츠를 함께 패키징하는 기존 용도를 유지한다.

게임을 종료하고 기존 `config/cobbleventure/content` 디렉터리를 새 번들의
동일 디렉터리로 **교체**한다. ZIP을 기존 파일 위에 풀기만 하면 삭제된
트레이너나 이벤트 파일이 남을 수 있다. 다른 사용자 설정은 교체하지 않는다.
개발 생성기는 자신이 만든 manifest가 있는 디렉터리만 교체하며, 교체 실패 시
이전 디렉터리를 복구한다.

멀티플레이 서버와 클라이언트에는 같은 번들을 설치해야 한다. 현재 자동 전송이나
접속 시 해시 비교는 구현하지 않았다. 서버만 바꾸면 로컬 지도·리그 정보가
다를 수 있다. 재시작은 Minecraft 프로세스 전체 재시작을 뜻한다.

`ContentPacks`가 번들을 서버 데이터팩과 클라이언트 리소스팩으로 등록한다.
없거나 계약 버전이 맞지 않으면 시작 과정에서 오류를 낸다.
`ContentFiles`는 서버 리소스 로더 생성 이전의 월드 생성과 정적 카탈로그가
같은 외부 파일을 읽도록 한다. JAR 내부 콘텐츠로 돌아가는 fallback은 없다.
개발 실행과 테스트는 Gradle에서 이 경로를 지정한다. 별도 실행에서는
`-Dcobbleventure.contentDirectory=<절대 경로>`로 재정의할 수 있다.

기존 CVES·퀘스트·전투 프리셋 재로딩은 유지하지만, 월드 생성과 정적 지도
캐시는 실행 중 변경을 지원하지 않는다. 기존 청크·배치된 NPC·플레이어 진행
상태를 새 콘텐츠에 맞춰 자동 이관하는 기능도 이 변경에 포함되지 않는다.

## 소유권과 변경 경계

- 정적 데이터·텍스처·모델·언어 파일: 콘텐츠 프로젝트의
  `content/resources/cobbleventure-<기능>/`. 엔진 소스 폴더를 빌드 입력으로 읽지 않는다.
- Blockbench 원본과 제작 스크립트: 콘텐츠 프로젝트의 `object-workspace/`.
  콘텐츠 빌더가 임시 작업장에서 변환하며 Gradle/JAR 빌드는 실행하지 않는다.
- 시작 세대·마을·진행 플래그: `content/catalogs/campaign.json`.
- 테마 블록 41종의 ID·동작 종류·강도·소리·지도색·밝기: `content/catalogs/theme-blocks.json`.
  기존 동작 종류로 블록을 추가할 때는 카탈로그와 모델·텍스처를 수정한다.
- 전투 AI 기술·종별 역할: `content/catalogs/battle-ai/`.
  전투 웹도 같은 원본을 읽는다.
- 음원·스폰 워크북·그림 생성 결과: 콘텐츠 ZIP에 함께 포함한다.
  이전 전용 Paxi 팩은 게임 콘텐츠 교체 시 백업 절차 안에서 제거한다.
- 건축 월드·라이브 NBT 편집 팩: 필요한 리소스만 별도 외부 콘텐츠로 생성한다.
  공통 콘텐츠 런타임을 함께 설치하며 게임 전체의 데이터팩을 로드하지 않는다.

Java에는 레지스트리 등록기, 블록 동작 구현, 월드 생성 알고리즘, 전투·UI 시스템,
네트워크와 저장 처리 등 엔진 기능이 남는다. 새로운 동작 종류나 콘텐츠 필드를
지원하는 엔진 기능을 추가할 때는 코드 변경이 필요하다.

클라이언트 자동 동기화, 무중단 갱신, 기존 세이브 마이그레이션은 별도 실행 기능이다.
현재 계약은 동일 콘텐츠 설치 후 게임 프로세스를 재시작하는 방식이다.

## 검증 기준

웹의 빌드 화면에서는 전체 빌드(`pack`), 모드팩 빌드(`mods-pack`), 콘텐츠 빌드
(`content`), 콘텐츠 교체(`content-install`)를 분리한다. 전체 빌드는 외부 콘텐츠를
CurseForge ZIP에 함께 넣고, 모드팩 빌드는 JAR·모드만 다시 빌드하여 별도
`cobbleventure-mods-<JAR 버전>.zip`을 만든다. 콘텐츠를 엔진 JAR에 다시 삽입하지 않는다.
웹에서 JAR 버전과 콘텐츠 버전을 독립적으로 저장하며, 전체 ZIP 이름에는 두 버전을
함께 표시한다. 콘텐츠 교체는 저장한 콘텐츠 버전의 ZIP만 사용한다.

콘텐츠 교체 대상은 `settings.local.json`의 `content_deployment.instance_path`에
저장한다. 교체 전에 번들의 프로젝트·계약 버전·파일 체크섬과 대상 엔진의 외부
콘텐츠 로더를 검사한다. 콘텐츠 디렉터리 전체와 관리 대상 스킨만 교체하고,
실패하면 백업을 복구한다. 복구까지 실패하면 원본 백업 경로를 오류에 표시한다.
게임을 종료한 상태에서 사용하며 저장 월드·JAR·다른 설정을 변경하지 않는다.

1. 콘텐츠 전체 검증과 관련 도메인 회귀 테스트.
2. 공통 런타임과 게임·건축 편집 모듈의 Java 테스트·JAR 빌드.
3. JAR에 `data/`, `assets/`가 없고 클래스·모드 메타데이터는 있는지 검사.
4. 트레이너 레벨을 바꾼 별도 프로젝트로 콘텐츠만 생성한 뒤 배포 JSON의 변경과
   엔진 JAR SHA-256 불변을 검사.
5. 삭제된 콘텐츠가 다음 번들에 남지 않는지, 생성 실패 시 기존 설치본을 유지하는지 검사.

커밋 메시지: `refactor: 주요 게임 콘텐츠를 엔진 JAR에서 외부 번들로 분리`

## 2026-09-11 검증 기록

- 다섯 모듈 Java 테스트 662개 통과, JAR 빌드 성공.
- 현재 버전의 다섯 JAR에서 `data/`, `assets/` 미포함 확인.
- 별도 프로젝트에서 알렉사 트레이너의 첫 포켓몬 레벨을 42 → 43으로 변경해
  콘텐츠만 생성했다. 배포 JSON은 43이 되었고 다섯 JAR의 SHA-256은 모두 유지됐다.
- 가방 조건·필드 기술 NPC·이벤트 이름 인덱스가 이전 Gradle 산출물과 일치했다.
- 콘텐츠 전체 검증 오류 0개. 신규 번들 테스트 3개, 팩 빌더 테스트 6개,
  자연 출현 테스트 10개와 퀘스트 패키징 테스트 2개 통과.
- 기존 테스트에서 변경하지 않은 데이터의 실패도 확인했다: 상점 NBT의
  `smooth_stone`/`polished_cut_calcite` 기대값 불일치, 길과 숲의 도윤 트레이너
  중복 배치, `league-facilities.html`의 CSS 로드 순서. 전체 웹 API 테스트는
  로컬 소켓 오류로 중단되어 전체 통과로 기록하지 않았다.
- Minecraft 실제 접속·플레이 검증은 아직 수행하지 않았다.
