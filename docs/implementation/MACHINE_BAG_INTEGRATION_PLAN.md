# 기계 공통 가방 연동과 기술머신 제작 구현 계획

상태: 1~4단계 공통 거래·세션·가방 패널·TM 제작 연결 및 5단계 완성 TM 획득 등록 구현. 2026-09-09 사용자 합의 기준.

첫 적용 대상은 Cobblemon 1.8 기술머신 제작기다. 기계를 열 때 바닐라 플레이어
인벤토리를 노출하지 않고, 우리 가방에서 재료를 사용하고 결과를 받는다.
등록한 기계부터 적용하며 모든 모드 화면을 무조건 교체하지 않는다.

관련 문서: [가방](BAG_INVENTORY.md), [기술머신 조사](COBBLEMON_1_8_TM_RESEARCH.md),
[원본 335종 제작표](COBBLEMON_1_8_TM_RECIPES.md), [연구소](ROUND_LABORATORY.md),
[연구 서비스](LABORATORY_RESEARCH_PLAN.md), [보호형 자원](PROTECTED_SURVIVAL_RESOURCES.md).

## 1 확정한 방향과 범위

- 기계 기능 영역과 공통 가방 영역을 함께 제공한다. 기계마다 가방을 새로 구현하지 않는다.
- 공통 계층은 세션·가방 조회·재료 차감·결과 지급·실패 안내를 맡는다.
- 기계별 연결 계층은 기능, 입력 조건, 제작법, 기계 상태 및 화면 세부 구성을 맡는다.
- 기술머신은 슬롯에 재료를 옮기지 않고 제작 버튼으로 가방 재료를 자동 차감한다.
- TM 제작법 발견은 Cobblemon의 기본 체계를 재사용하고, 획득한 완성 TM도 자동 등록한다.
- 제작 재료는 빈 디스크와 타입 잼 중심으로 단순화한다.
- 빈 디스크 구매, 잼 교환, 지역별 반복 수급을 연결한다.
- 가방에서 TM을 사용해 파티에 기술을 가르치는 기존 흐름과 이어진다.

이번 첫 버전의 완료 범위는 공통 처리와 TM 제작·획득이다. 화로·상자 등의 수동 슬롯
이동 기능, 모든 모드의 자동 호환, 자동화·호퍼 제작까지 같은 규칙으로 통합하는 작업은
후속 대상이다. 공통 설계에 확장 지점을 남기되 미사용 기계 기능을 먼저 구현하지 않는다.

## 2 현재 구조와 재사용 경계

| 기존 구성 | 재사용 / 필요한 변경 |
| --- | --- |
| `BagStorage` | 4,096칸 확장 저장소, 컴포넌트 보존, 작업 사본과 저장 방식 재사용 |
| `BagApi` | 조회·지급 API 재사용. 여러 재료 차감과 결과 지급을 묶는 원자적 거래 추가 |
| `BagNetwork` | 가방 동기화와 지급 연결 활용. 기계 세션은 별도 네트워크 계층으로 분리 |
| `BagScreen` | 분류·검색·목록 처리 중 필요한 부분을 재사용 가능한 가방 패널로 추출 |
| `ShopNetwork` | 토큰·거리·재화 검사 등 동작 패턴 참고. 기존 상점을 한꺼번에 개편하지 않음 |
| `MenuTheme`, `ThemedOverlayPanel`, `MenuBackButton` | 모든 신규 화면과 버튼에 적용 |
| Cobblemon TM 등록부·플레이어 해금 데이터 | 기술 목록, 기술 속성, 학습 호환성, 해금 판정의 기준 |

현재 `BagApi.insertAll`은 일괄 지급을 지원하지만 개별 `remove`와 `insert`를 나란히
호출하는 것만으로 제작 전체가 원자적이 되지는 않는다. 제작 공통 거래가 먼저 필요하다.
기존 단독 가방·상점·연구 서비스의 동작은 이 작업에서 불필요하게 변경하지 않는다.

## 3 공통 구조

```text
등록된 기계 우클릭
  → 기계별 연결 계층: 사용 가능 여부 / 해당 기계 식별
  → 서버 세션 생성
  → 공통 기계 화면: 기계 기능 영역 + 가방 영역
  → 사용자가 동작 요청
  → 서버 재검증 + 가방 거래 계획
  → 한 번에 적용하고 결과·가방·기계 화면 동기화
```

예정 책임 구분(명칭은 구현 시 조정 가능):

- `MachineBagSession`: 플레이어, 기계 종류, 차원·위치, 세션 토큰, 유효시간, 상태 버전.
- `MachineBagAdapter`: 기계별 접근 조건, 화면 데이터 생성, 허용 작업과 실행 검증.
- `BagTransaction`: 재료 선택·수량 검증·비용 차감·출력 공간 검증·결과 반영.
- `MachineBagPanel`: 검색·분류·아이템 수량·재료 부족 상태 표시. 자체 저장소를 만들지 않는다.
- `TmWorkshopAdapter` / TM 화면: 등록 TM 목록, 해금, 제작·디스크 구매·잼 교환.

표준 컨테이너 슬롯을 사용하는 기계는 향후 공통 슬롯 연결 계층을 추가할 수 있다.
특수 패킷이나 독자 데이터를 쓰는 기계는 별도 연결이 필요하다. 클라이언트 화면만
바꿔도 원래 기계의 서버 슬롯이 가방을 읽게 된다고 가정하지 않는다.

## 4 가방 거래 계약

### 재료와 결과

- 재료 보유량은 가방이 실제로 표시하는 일반 인벤토리·핫바·확장 가방의 실물 스택을
  한 번씩 집계한다. 바로가기 설정에 저장된 아이템 견본은 수량에 포함하지 않는다.
- 첫 버전 차감 순서는 확장 가방 우선, 부족분은 일반 인벤토리·핫바 순서로 둔다.
  보유 수량과 서버 차감 대상의 범위를 동일하게 유지한다.
- 수량 계산에는 오버플로 방지와 요청 수량 상한을 둔다.
- TM 결과는 기술 컴포넌트를 보존해 확장 가방에 지급한다.
- 제작 후 재료가 빠져서 생기는 빈 공간까지 고려해 결과 수용 여부를 판단한다.
- 재료 부족·공간 부족·잔액 부족·잠긴 제작법은 아무것도 소모하지 않고 실패한다.
- 아이템·재화 변경은 작업 사본에서 검증한 뒤 적용한다. 재화 저장이나 결과 반영 실패 시
  원상 복구하고, 재요청으로 결과만 중복 지급되지 않도록 한다.

### 요청과 세션

- 클라이언트는 기계 작업 ID·기술 ID·수량을 요청한다. 가격, 결과물, 해금 여부를 결정하지 않는다.
- 서버는 매 요청마다 거리·차원·기계 존재·배틀 여부·세션 소유자와 최신 제작법을 확인한다.
- 세션 토큰과 작업 ID로 중복 클릭·재전송을 구분한다. 같은 작업은 재실행하지 않고 같은 결과를 반환한다.
- 화면에 보인 가방 슬롯 번호만 신뢰하지 않는다. 다른 작업으로 가방이 정렬·이동되면 최신 상태에서 검증한다.
- ESC·뒤로 버튼·거리 이탈·기계 파괴·차원 이동·로그아웃 시 세션을 닫는다.
- 입력 아이템을 임시로 기계에 보관하지 않는 TM 제작은 취소만으로 아이템 이동이 발생하지 않는다.
- 데이터 리로드 후에는 세션을 갱신하거나 무효화해 옛 비용으로 제작되지 않도록 한다.

## 5 첫 화면: 기술머신 제작소

일반 우클릭 시 전용 화면을 연다. 바닐라 제작 화면이 동시에 열리지 않도록 서버의
진입 동작과 클라이언트 화면을 함께 처리한다. 기계 접근은 보호 구역의 사용 권한과도 확인한다.

| 영역 | 표시·동작 |
| --- | --- |
| 상단 | 제작소 이름, 기술 검색, 타입 필터, 해금/전체 보기 |
| 기술 목록 | 기술명·타입·해금 상태. 목록은 스크롤하고 선택을 유지 |
| 기술 상세 | 분류, 위력, 명중률, PP, 설명 |
| 파티 | 배울 수 있음 / 이미 알고 있음 / 배울 수 없음 |
| 가방·필요 재료 | 빈 디스크와 잼의 필요량·보유량, 부족 재료 표시 |
| 제작 | 수량 선택, 합계 비용, 제작 가능 여부, 서버 결과 안내 |
| 재료 서비스 | 빈 디스크 구매, 남는 잼 교환 |
| 하단 | 항상 보이는 뒤로 버튼 |

잠긴 기술은 선택해 설명을 읽을 수 있지만 제작할 수 없다. 해금 안내는 확인된 조건만
표시한다. ‘관련 포켓몬의 기술 확보 또는 TM 획득’과 기본 해금/특수 조건을 구분하고,
조사하지 않은 정확한 출현 장소를 추측해 안내하지 않는다.

작은 해상도에서는 두 영역을 탭 또는 세로 스크롤로 전환한다. 클릭 가능한 요소와
재료·제작 버튼이 화면 밖으로 밀리지 않도록 한다. 폰트·상태 색·버튼은 전역 테마를 사용한다.

## 6 TM 해금과 제작 데이터

- 원본 TM 등록부를 기준으로 제작법을 관리한다. 현재 조사 기준은 335종이며 버전 변경 시 재검증한다.
- 기존 타입 잼 요구량과 보조 타입 잼은 우선 유지하고 바닐라·도구 부재료를 제거한다.
  빈 디스크 1개를 별도 공통 비용으로 표시·차감한다.
- 코블몬과 우리 화면에 서로 다른 제작법이 보이지 않도록 서버 콘텐츠를 단일 기준으로 사용한다.
- 원본 호퍼/자동화 경로가 남는 경우 단순화된 비용이 일치하는지 확인한다.
  비용·해금 우회가 생기는 자동화 경로는 첫 버전에서 비활성화하고 안내한다.
- 정의가 없는 발전과제를 참조하는 메가드레인은 일반 발견형 해금으로 교체하는 안을 적용 검증한다.
- 재료 변경 파일은 콘텐츠 원본으로 관리하고 빌드 시 패키징한다. 335개 수동 복사를 반복하지 않도록
  원본 대비 생성·검증 절차를 둔다.

### 완성 TM 획득 시 자동 등록

상점, NPC/퀘스트, 던전 보상, 가챠, 바닥 줍기, 다른 플레이어에게 받은 TM을 대상으로 한다.
서버가 실제 획득 완료를 확인한 뒤 기술을 등록한다. 견본 표시·구매 미리보기·실패한 지급으로는 등록하지 않는다.
등록을 위해 TM을 소모하지 않으며 이미 등록한 기술의 알림을 반복하지 않는다.
기존 보유 TM은 접속 또는 최초 가방 동기화에서 보정한다. 등록부를 매 틱 전부 순회하는 방식은 피한다.

구현은 확장 가방의 저장 완료 경계에서 즉시 확인하고, 공통 가방 API를 거치지 않는 명령·타 모드의
바닐라 인벤토리 지급은 1초 간격의 36칸 검사로 보완한다. 잠긴 제작법을 처음 발견했을 때만 Cobblemon의
기본 TM 해금 API를 호출하므로 기술명과 함께 작은 기본 토스트가 한 번 표시되고, 저장·클라이언트 동기화와
TM 관련 발전과제도 원본 규칙대로 처리된다. 기본 해금 TM과 전체 해금 설정에서는 중복 등록 알림을 띄우지 않는다.

완성 TM은 중요한 도구처럼 버리기·폐기·판매·포켓몬 지니기를 금지한다. 사망 시 일반 인벤토리의
TM도 땅에 생성하지 않고 확장 가방으로 회수한다. 이를 통해 플레이어들이 같은 TM을 돌려 쓰며
각자의 제작법을 여는 경로를 차단한다.

포켓몬 기반 해금은 원본의 광범위한 접근 가능 기술 동기화를 그대로 사용하지 않는다. 교환이 아닌
방법으로 포켓몬을 새로 얻었을 때는 그 포켓몬이 현재 알고 있는 기술만 등록한다. 보유 포켓몬이
레벨업할 때는 이전 레벨을 초과하고 새 레벨 이하에서 배우는 기술만 등록한다. 교환으로 받은
포켓몬의 기술은 등록하지 않으며, 이후 그 포켓몬이 직접 레벨업하여 새로 배우는 기술은 등록한다.

## 7 빈 디스크와 잼 수급

- 빈 디스크는 제작소에서 게임 머니로 구매한다. 가격은 경제 콘텐츠에서 관리한다.
- 잼 교환은 입력 타입·출력 타입·수량·손실 비율을 명시한다. 동일 타입 교환은 허용하지 않는다.
- 18타입 모두에 반복 획득 경로 또는 교환 경로를 보장한다.
- 기존 던전 보상 테이블을 지역별로 나누어 연결한다. 예: 발전소 전기·강철, 포켓몬타워
  고스트·독, 숲 풀·벌레. 실제 배치와 보상 상자/클리어 조건까지 확인한다.
- 던전별 보상 소유권·재입장·반복 클리어 정책을 확인한다. 테이블만 존재하는 상태로 완료하지 않는다.
- 다른 연구 서비스도 잼을 소비하므로 Z크리스탈 등과 공급량·판매 수익을 함께 계산한다.
- 재생형 광물 노드와 코어 재배는 후속 수급 확장이다. 첫 버전의 작동 조건으로 의존하지 않는다.

빈 디스크 가격, 교환 비율, 지역별 지급량은 아직 확정 수치가 아니다. 구현 시 콘텐츠 초안으로
분리하고 대표 TM 한 장당 필요한 지역 활동 횟수와 기존 완성품 상점 가격을 비교해 조정한다.
이번 계획 작성에서는 임의의 수치를 출시값으로 확정하지 않는다.

## 8 구현 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 가방 거래 공통 계층 | 다중 재료 차감+결과 지급+재화 처리가 실패·중복 요청에도 정확히 한 번 적용 |
| 2 | 기계 세션과 화면 틀 | 등록된 TM 제작기만 연결, 기본 인벤토리 미노출, 뒤로/이탈 시 정상 종료 |
| 3 | 재사용 가방 패널 | 분류·검색·보유 수량 표시, 단독 가방 기능 회귀 없음 |
| 4 | TM 화면과 제작 연결 | 해금·기술 상세·파티 호환·필요 재료·수량 제작을 서버 기준으로 실행 |
| 5 | 획득 등록·디스크·교환 | 실제 획득 후 자동 등록, 구매·교환의 비용/수량 정확성 |
| 6 | 지역 수급·연구실 배치 | 실제 진입 가능한 제작기와 반복 보상 연결, 18타입 공급표 완성 |
| 7 | 통합 검증·개발 팩 반영 | 콘텐츠 검증·빌드·회귀 테스트 통과, 새 인스턴스와 기존 월드 확인 |

기능 단위 권장 커밋 메시지:

1. `feat: 기계 연동용 공통 가방 거래와 세션 처리 추가`
2. `feat: 기술머신 제작기에 공통 가방 화면 연결`
3. `feat: 기술머신 획득 자동 등록과 잼 기반 제작 지원`
4. `feat: 연구소 재료 교환과 지역별 잼 수급 연결`

## 9 검증 계획

자동 검증:

- 실제 거래 로직의 재료 분산, 부분 부족, 출력 공간, 최대 수량, 컴포넌트 보존 테스트.
- 중복 작업 ID, 잘못된 세션, 기계 이탈, 재화 오류에서 소모/지급이 남지 않는지 확인.
- TM 변형별 결과, 미해금 제작 거부, 획득 실패 시 미등록, 기존 보유 TM 보정 테스트.
- 전 TM의 디스크·잼 전용 비용, 기본 해금 유지, 잘못된 메가드레인 참조 제거 검사.
- 전체 콘텐츠 검증, 관련 모듈 빌드·테스트, 테마 콘텐츠 계약, 구조물 생성 회귀 테스트.
- 순수 제작/보상 변경으로 포켓몬 출현 데이터를 수정하지 않는다. 향후 출현 변경 시 별도 지침을 선행한다.

인게임 확인:

1. 연구소 제작기를 열어 바닐라 인벤토리가 뜨지 않는지 확인한다.
2. 검색·타입 필터·잠긴 기술·파티 학습 상태·작은 해상도·키보드 이동을 확인한다.
3. 가방·핫바에 분산된 재료로 제작하고 정확한 차감 및 결과 TM의 기술을 확인한다.
4. 결과 TM을 가방에서 사용해 파티 포켓몬이 배우는 것까지 확인한다.
5. ESC, 거리 이탈, 기계 파괴, 재접속, 가방 정렬, 중복 클릭, 가득 찬 가방을 확인한다.
6. 상점·가챠·NPC·던전·줍기로 얻은 TM이 등록되고 버리기·판매·지니기가 차단되는지 확인한다.
   교환 포켓몬의 기존 기술은 등록되지 않고, 비매매 획득 당시 기술과 이후 레벨업 기술만 등록되는지 확인한다.
7. 던전 반복 획득→잼 교환→디스크 구매→TM 제작의 전체 동선을 확인한다.
8. 기존 상점·회복 아이템·기술머신 사용·연구소의 다른 서비스에 영향이 없는지 확인한다.

코드 검증 통과와 인게임 검증 완료는 별도로 기록한다. 기존에 생성된 연구소 내부는
구조물 파일 교체만으로 갱신되지 않을 수 있으므로 업데이트 정책을 함께 안내한다.

## 10 현재 작업 상태

`BagTransaction`이 일반 인벤토리와 확장 가방의 작업 사본에서 다중 재료 차감과
결과 지급을 먼저 검증한 뒤 한 번에 반영하는 1단계 기반을 제공한다. 재료는 확장 가방부터
차감하고 결과는 확장 가방에 넣으며, 재화·기계 상태는 되돌릴 수 있는 `SideEffect`로 같은
커밋 경계에 참여한다.

`cobblemon:tm_machine` 우클릭은 서버 권위 `MachineBagNetwork` 세션을 열며, 세션은
소유자·차원·위치·기계 종류·거리·만료·배틀 상태를 검증한다. 전용 화면 골격은 바닐라
인벤토리를 노출하지 않고 공통 테마와 뒤로 버튼을 사용한다. 거리 이탈, 기계 제거, 차원 이동,
로그아웃과 명시적 닫기에서 세션을 정리한다. 세션별 작업 원장은 동일 작업 ID의 진행 중 요청,
완료 요청 재전송과 다른 내용의 충돌을 구분한다. 실제 기술 목록·해금·제작 요청 연결은 다음 단계다.

`BagItemCatalog`가 단독 가방과 기계 가방 패널의 분류·이름/설명 검색 규칙을 함께 제공한다.
TM 제작소의 `MachineBagPanel`은 일반 인벤토리와 확장 가방에서 컴포넌트가 같은 아이템을
하나로 합산해 이름과 정확한 총수량을 표시하며, 검색과 휠 스크롤 및 툴팁을 지원한다.
이 패널은 읽기 전용이며 저장소나 차감 로직을 복제하지 않는다.

TM 제작소는 Cobblemon 서버 TM 등록부에서 기술·타입·분류·위력·명중률·PP·설명·해금과
최대 3개 제작 재료를 읽는다. 기본 해금 설정, 기본 TM과 플레이어의 학습 목록을 같은 기준으로
판정하며, 검색·타입 필터·해금/전체 보기·파티 호환·1~64장 수량 선택을 제공한다. 제작 요청은
기술 ID와 수량만 보내고 서버가 빈 디스크와 최신 제작법, 해금, 세션 및 보유 재료를 재검증한 뒤
`BagTransaction`으로 차감과 TM 컴포넌트가 포함된 결과 지급을 한 번에 반영한다.

앞서 작성된 `content/tms/cobblemon`의 단순화 제작법 초안은 이 계획의 데이터 후보이며,
패키징·최종 검증을 거친 완료 콘텐츠로 간주하지 않는다.
