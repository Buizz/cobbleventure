# 칸토리그 시설과 진행 설정

## 웹에서 관리하는 위치

콘텐츠 관리 → **리그 운영 → 리그 시설** 탭 (`/?section=league-facilities`).
리그 구성·체육관 시설 옆 세 번째 탭이며, 기존 `/league-facilities.html` 주소도 이 탭으로 이동한다.
원본은 `content-projects/cobbleventure-main/content/catalogs/league-facilities.json`이다.

- 리그별 로비, 순서대로 배치한 엘리트 방, 마지막 챔피언 방, 명예의 전당을 지정한다.
- 위쪽에서 엘리트 4명·챔피언 1명을 선택하고 아래쪽에서 대응하는 방 5개를 선택한다. 다른 엘리트를 선택하면 두 위치의 트레이너가 서로 바뀌며 NPC ID와 리그 구성의 편집 데이터는 유지된다.
- 방 선택은 기존 NBT 검색 대화상자를 사용한다. 필요한 마커가 있는 내부만 표시하며, 입장·출구·NPC 위치는 화면에서 따로 지정하지 않는다. 로비의 기존 간호순·상점·럭키 배치는 그대로 유지한다.
- 전투 구성은 5칸으로 고정한다. 로비·명예의 전당, 입장 조건과 회차 설정은 접을 수 있는 별도 영역에 둔다. 저장·다시 불러오기·삭제는 다른 탭과 같은 상단 고정 헤더에 둔다.
- 입장 조건은 공용 조건 편집기로 배지·플래그·아이템·변수·파티 조건 등을 조합한다.
- 진행 방식은 `checkpoint`(이어하기) 또는 `relay`(릴레이)를 선택한다.
- 저장 → 콘텐츠 생성 → 데이터 모드 빌드 → 서버 재시작 순서로 반영한다.

현재 칸토리그는 **관동 배지 8개 모두 필요 / 이어하기**로 설정되어 있다.
입장 조건은 외부에서 로비에 들어올 때와 로비에서 도전을 시작할 때 확인한다.

## 외부 건물 연결

기존 `structures/league/kanto_league.nbt` 원본 건축은 보존했다. 월드맵의 석영고원은 `cobbleventure:league/indigo_plateau`를 사용한다.
공식 《레츠고》의 [석영고원 정면](https://pokemonletsgo.pokemon.com/assets/img/kanto-region/p02_01.jpg)을 확인하고 3D 도형부터 다시 설계했다. 부지는 130×162블록, NBT 높이는 여유 공간을 포함해 72블록이다. 중앙 계단은 폭 26블록이며 정문 광장까지 3단 계단으로 24블록 상승한다. 4방향 컨셉에 맞춘 네 모서리 탑과 옆면·후면의 세로 창, 높은 입구, 낮은 지붕과 세 줄의 꺾인 측면 장식을 사용한다. 중앙 길 위를 덮는 아치는 없다.

- 공유 모델: `tools/structure-builder/indigo_plateau_model.py`
- 회전 가능한 예제: `docs/assets/indigo-plateau/index.html` (전체·정면·후면·좌측·우측·플레이어 시점)
- 편집 가능한 glTF 모델: `docs/assets/indigo-plateau/indigo-plateau.glb`
- `compile_indigo_model.py`가 같은 도형을 glTF와 블록 배열로 변환한다. 후면은 보완 설계이고, 게임 원본 모델을 추출하거나 사진을 자동 복원한 결과는 아니다.
- 예제의 2블록 사람은 크기 비교용으로만 표시하며 NBT에는 배치하지 않는다.

새 외부 건물은 `door` 마커 하나만 지정하고 일반 NBT 연결 화면에서 로비 입장점에 연결한다.

```text
exterior:door -> lobby:entry
```

별도 외부 복귀 마커는 필요 없다. 빌드 시 `lobby:leave -> exterior:door`를 자동 생성하며,
문의 안전한 바깥 위치(`safe_spawn`)로 돌아온다. 여러 외부 입구를 연결할 때만 복귀할 문을
명시해야 한다. 명시한 연결은 자동 역방향 연결보다 우선한다.

임시 외관 정문에는 `door`라는 transition 마커 하나를 둔다. 위치는 `[65, 27, 56]`, 안전 복귀점은 `[65, 25, 66]`이며, 정문의 폭 10·높이 6·깊이 2 배리어에 접근하면 로비로 이동한다. 기존 탑의 외부 연결은 해제하고 새 외관에 `exterior:door -> lobby:entry`만 연결했다. 로비 복귀는 컴파일러가 자동 생성한다.

재현 스크립트는 `tools/structure-builder/generate_indigo_plateau.py`이다. 기본 실행은 기존 파일 덮어쓰기를 거부하고, 일반 콘텐츠 빌드는 저장된 NBT만 사용하므로 이후 수작업 건축을 보존한다.

외부 건물에는 엘리트 방·챔피언 방·명예의 전당을 직접 연결하지 않는다.
로비의 `exit`부터 명예의 전당까지는 리그 설정으로 자동 생성되며, 일반 연결 화면에서는 숨긴다.
로비 NBT를 바꾸거나 연결된 리그를 삭제·ID 변경할 때는 먼저 외부 로비 연결을 해제한다.

## 분리된 방 NBT와 마커

모든 내부는 기존 체육관과 같은 `cobbleventure:building_interiors` 차원에 배치한다.
각 방은 독립된 배치 공간을 사용하며, 원본 건축의 층을 복사해 만들었다.
NBT를 직접 편집할 수 있고, 원본 탑과 편집한 방을 자동으로 서로 덮어쓰지 않는다.

| 용도 | NBT 리소스 ID |
| --- | --- |
| 로비 | `cobbleventure:interiors/leagues/kanto_lobby` |
| 첫 번째 엘리트 | `cobbleventure:interiors/leagues/kanto_elite_1` |
| 두 번째 엘리트 | `cobbleventure:interiors/leagues/kanto_elite_2` |
| 세 번째 엘리트 | `cobbleventure:interiors/leagues/kanto_elite_3` |
| 네 번째 엘리트 | `cobbleventure:interiors/leagues/kanto_elite_4` |
| 챔피언 | `cobbleventure:interiors/leagues/kanto_champion` |
| 명예의 전당 | `cobbleventure:interiors/hall_of_fame` |

로비에서 사용할 이름:

```text
entry       arrival       입장 위치
exit        transition    리그 도전 / 이어하기
leave       transition    외부 건물 복귀
nurse       npc_position  간호순
shop        npc_position  상점 NPC
chansey     npc_position  럭키
```

모든 엘리트·챔피언 방에서 공통으로 사용할 이름:

```text
entry                   arrival       방 입장 위치
exit                    transition    승리 후 다음 방
opponent                npc_position  상대 NPC
opponent_battle_player  arrival       플레이어 전투 위치
```

명예의 전당:

```text
hall_entry  arrival       챔피언 방에서 도착
hall_exit   transition    로비로 자유롭게 복귀 (클리어 유지)
```

기존 `champion_exit` 역할은 분리된 챔피언 방의 `exit`가 담당한다.
**명예의 전당 NBT로 실제 연결하며, 임시 `return` 우회는 사용하지 않는다.**
명예의 전당 건축은 별도 편집 가능하며, 현재는 입장·복귀 공간이다.
파티 전시 저장·전용 등록 연출은 이번 변경 범위에 포함하지 않았다.

각 NBT에는 같은 이름의 `.structure.json`이 필요하다. 전환 마커 위치는 실제
배리어/문과 맞추고, 도착점과 전투 위치는 발판 위 두 칸이 비어 있어야 한다.
각 방은 다른 리그와 중복 등록하지 않는다. 동일 건축을 재사용하려면 NBT를 복사해서 지정한다.

## 전투와 진행도

리그 구성에서 **사천왕·챔피언**을 선택하면 관장과 같은 공통 편집기로 포켓몬·기술·성격·특성·도구·IV/EV를 설정한다. 엔트리 복사·붙여넣기와 기존 트레이너 엔트리 가져오기도 지원한다.

말을 걸어 도전하면 `opponent_battle_player`로 플레이어를 이동시켜 NPC와 마주 보게 한다.
방이 사용 중이거나 전투 위치가 막혔으면 전투를 시작하지 않는다.
서버는 현재 도전의 정확한 방·NPC 인스턴스·전투 결과를 확인한 뒤 진행도를 증가시킨다.
다른 방 선행 진입이나 이전 승리 플래그만으로 다음 방을 여는 것은 허용하지 않는다.

| 상황 | 이어하기 | 릴레이 |
| --- | --- | --- |
| 승리 | 다음 단계 저장 | 현재 도전의 다음 단계 저장 |
| 패배·도주 | 로비 복귀, 마지막 승리 다음부터 | 로비 복귀, 첫 방부터 |
| 클리어 전 리그 이탈·접속 종료 | 승리 단계 유지 | 첫 방으로 초기화 |
| 클리어 전 재접속 | 로비에서 이어하기, 중단된 전투 자체는 재개하지 않음 | 로비에서 새 도전 |
| 클리어 후 로비 입장 | 명예의 전당 자동 입장 | 동일 |
| 명예의 전당 출구 | 로비로 복귀, 클리어 유지 | 동일 |
| 클리어 후 접속 종료 | 클리어 유지 | 동일 |

현재 방에서 승리하면 출구로 나아간다. 같은 도전에서 이미 이긴 상대는 다시 전투할 수 없다.
클리어한 회차에서는 재도전을 자동 시작하지 않는다. 플레이어별 진행도를 따로 저장한다.
명예의 전당에서 돌아온 로비에서는 외부로 자유롭게 나갈 수 있으며 전당으로 다시 끌려가지 않는다.

트레이너 카드의 영구 승리 업적과 이번 도전 진행도는 별개다.
`cobbleventure:flag/league/kanto/<elite_1|elite_2|elite_3|elite_4|champion>/defeated`는
현재 회차의 업적으로 남고, 리그 이탈이나 릴레이 중단으로 지우지 않는다.
향후 회차 전환에서는 이 플래그도 회차 프로필에 보관하고, 계정 전당 이력은 별도로 유지한다.
기존 업적에서 새 도전 단계를 추정하지 않으므로 이번 체계의 첫 도전은 첫 방부터 시작한다.

NPC·대사·파티의 유일한 편집 원본은 `league-facilities.json`의 각 단계 `trainer`다.
별도 NPC를 만든 뒤 배정하거나 배틀 프리셋을 따로 저장할 필요가 없다.
`trainer`에는 `name`, `appearance`, `dialogue`(도전·플레이어 승리·패배), `battle`을 저장한다.
NPC·배틀·CVES 이벤트·바인딩은 빌드 시 자동 생성한다. ID는 리그/단계 ID에서 파생하며
기존 칸토 5명의 ID·승리 플래그·대사·외형·엔트리는 보존했다.
기존 `source/league`, `battles/league`, `events/.../league`, `event-bindings/.../league`의
해당 5명 원본 파일은 설정으로 이전하여 제거했다. 직접 작성한 같은 ID의 원본을 다시 만들지 않는다.
리그 구성 탭에서 사천왕·챔피언을 선택하면 대사·외형과 공통 포켓몬 엔트리 편집기가 바로 표시된다. 리그 시설 탭과 같은 trainer 데이터를 편집하고 저장하므로 별도 NPC를 선택할 필요가 없다. 사천왕·챔피언에는 배지 설정과 목록 배지 칸을 표시하지 않는다. 관장도 배틀 프리셋을 직접 지정하지 않고 이 페이지에서 엔트리를 편집하며, 기존 battle_id 연결은 내부적으로 유지한다.

## 기존 월드와 구현

`league_facilities.py`가 원본 건물 설정의 로비 연결을 빌드 시 확장한다.
생성 리소스의 `runtime_league`와 자동 경로를 원본 `building-settings.json`에 되돌려 쓰지 않는다.
`LeagueRuntimeSystem`이 입장, 진행 순서, 재접속·패배·이탈 처리를 담당한다.

방 NBT·메타데이터·배치·순서를 바꾸면 새 배치 공간을 사용한다. 이전 방을 다른 방으로
덮어쓰지 않으며, 호환되지 않는 미완료 도전은 초기화하지만, 클리어 기록은 유지한다. 중단된 도전의 재접속 시 미완료라면 현재 로비, 클리어했다면 명예의 전당으로 복귀한다.
과거 월드에 이미 생성된 NPC나 사용하지 않는 옛 내부 공간은 자동 삭제하지 않는다.
이전 위치에 남은 리그 상대는 전투를 차단한다. 불필요한 옛 배치는 건축 정리 시 제거할 수 있다.

`tools/structure-builder/split_kanto_league.py`는 최초 추출용이며, 방 파일이 존재하면
덮어쓰지 않고 중단한다. 추출 후 수작업으로 수정한 방이 정식 원본이다.

## 검증

- 콘텐츠 전체 검증 및 CVES 이벤트 컴파일
- 리그 설정 검증, 단계별 경로, NBT 마커·안전 발판, 외부 그래프 저장 왕복 회귀 테스트
- 진행 방식·중복 결과·순서 건너뛰기·클리어 유지·전당 출구 재진입 방지에 대한 Java 테스트
- 웹 화면에서 진행 방식 변경 및 저장 확인
- 실제 Minecraft에서 입장 → 전투 위치 이동 → 연속 승리 → 명예의 전당,
  패배·도주·재접속과 동시 도전은 최종 인게임 확인이 필요하다.

## 다음 회차 등록

명예의 전당은 다음 회차로 넘어가기 전 거점이다. 출구 이용은 회차 전환이 아니다.
등록·회차 선택·아이템/포켓몬 보관 및 복원 설계는 [회차별 프로필](PLAYTHROUGH_PROFILES.md)을 따른다.
현재 자산 초기화와 실제 회차 전환은 활성화하지 않았으며, 저장·복구 제공자 구현이 먼저 필요하다.

## 다음 세대 이동 테스트

세대 맵 하나가 하나의 회차다. 현재 칸토 리그는 `generation: 1`, `next_generation: 2`,
`generation_travel_mode: travel_test`로 설정했다. 전당의 `hall_next_generation`은 2세대
시작마을의 플레이어 집 `room_1:start`로 이동한다. `hall_exit`는 계속 로비로 돌아간다.
테스트에서는 모든 아이템·포켓몬을 유지하며, 정식 전당 등록/자산 분리는 아직 설계 단계다.
설정과 왕복 확인 방법은 [회차별 프로필 설계](PLAYTHROUGH_PROFILES.md#2세대-이동-테스트-설정)를 참고한다.

### 4방향 컨셉 기반 외관 개정

`docs/assets/indigo-plateau/concept-four-views.png`를 건축 참고로 사용한다. 세 겹의 석축과 화단이 측면과 후면까지 이어지며, 앞쪽 중앙 계단은 폭 26블록을 유지한다. 창·장식의 곡선과 세부 표현은 마인크래프트 블록 격자에 맞춰 해석했다. 마커의 X/Z와 로비 연결은 유지하고, 높아진 기단에 맞춰 Y만 12블록 올렸다.
