# 리그 아치길

길 설정의 `길 종류`에서 **리그 아치길** (`league_arch`)을 선택하고 저장한다. 기존 도로 바닥 생성 규칙을 사용하며, 길 생성 뒤 아치·조각상 모듈을 8블록 간격으로 배치한다. 포켓몬 출현·레벨·음악 설정은 변경하지 않는다.

## 분리한 NBT

- `cobbleventure:road_decorations/league_arch`: 첫 아치와 조각상
- `cobbleventure:road_decorations/league_arch_2`: 두 번째 아치와 조각상
- `cobbleventure:road_decorations/league_arch_3`: 세 번째 아치와 조각상
- `cobbleventure:road_decorations/league_approach`: 원래 장식 전체를 함께 배치하기 위한 보존본

반복 모듈은 폭 20, 높이 12, 깊이 12(마지막 11)블록이다. 원본 블록 상태와 블록 엔티티 태그를 유지했다. 길 바닥 및 공기 블록은 포함하지 않으므로 NBT 배치가 기존 길을 지우지 않는다. 좌우 기둥의 밑동에는 원래 흙 블록이 남아 있다.

## 배치 범위

입구 여유 공간으로 양 끝 18블록을 비우고, 아치 중심을 길의 누적 거리 기준 8블록마다 반복 배치한다. 대각선은 가장 가까운 90도 방향을 사용하고, 깊이별 가로 위치를 길 기울기에 맞춰 이동하여 통로가 도로를 따라가게 한다. 급커브와 짧은 구간은 건너뛴다. 높이는 상단 배리어가 포함되는 최고 블록 높이가 아니라 실제 도로 지형 계획을 사용한다. 전체 NBT 사각형 대신 실제 배치 블록만 장애물을 검사하며, 지면 차이가 8블록 이내인 밑동에는 받침을 둔다. 건물·나무 등 점유 블록이나 물을 침범하는 후보는 건너뛴다. 변경한 길은 월드의 길/지형을 다시 생성해야 적용되며 기존 월드를 자동으로 지우지 않는다.

## 석영고원 분리

`league/indigo_plateau.nbt`는 60×72×80에서 60×72×45로 줄였다. Z=45 이후 아치와 장식을 분리하고 앞길은 제거했다. Z=42~44의 길 바닥도 제거했다. 메인 건물과 문 앞 한 줄의 복귀 바닥은 보존했다. `door` [29,1,40] 및 복귀점 [29,1,41]을 변경하지 않았다.

분리 전 전체 원본: `backups/indigo-plateau/20260912-130222-split/`. 재현 스크립트: `tools/structure-builder/split_indigo_approach.py`. 스크립트는 원본 크기를 확인해 중복 분리를 거부한다.

## 2026-09-14 수정

`route_custom_23`의 프리셋은 정상적으로 `league_arch`로 컴파일된다. 기존 누락 원인은 대각선 전부 제외와 상단 배리어를 포함한 높이 조회였다. 원본 NBT는 유지하고 런타임 배치만 변경했다.
석영고원 도로 끝점은 별도로 저장된 `road_anchor` 또는 `door`/`transition` 마커가 필요하다. 실제 문 블록을 자동 탐색하지 않는다.

## 네이티브 생성 연결 수정

네이티브 청크 생성은 `drawHexWorld`를 실행하지 않는다. 따라서 아치 생성은 네이티브 초기화의 오브젝트 배치 다음에도 호출한다. `WorldPlanRepository` 역시 런타임과 동일한 `CenterStructureRoads.connect`로 경로를 보정하며, 서버 레벨이 없어도 외부 콘텐츠 NBT와 마커를 읽어 계산한다. 기존 네이티브 청크는 보정 전 경로가 이미 지형으로 구워져 있으므로 새 월드 또는 해당 지형 재생성이 필요하다.

현재 사용자가 저장한 `door`는 `[29,1,42]`, 복귀점은 `[29,1,43]`이다. 실제 패키지 콘텐츠 통합 테스트 결과 석영고원 도로 입구 X/Z는 `[-177, -471]`이며 아치 배치 후보 수는 8블록 간격과 급커브 검사에 따라 계산한다. 최종 배치 수와 장애물·급경사에 의한 제외는 서버 로그 `League arches`의 `placed`와 `rejected`로 확인한다. 개별 제외 좌표는 DEBUG `League arch rejected`에 기록한다. 후보가 있지만 하나도 설치되지 않으면 WARN, 모듈 누락 및 템플릿 배치 실패는 ERROR를 기록한다. 인게임 화면 검증은 별도다.

## 아치 배치 사전 검사

`RoadArchPlan`은 실제 NBT 블록과 받침이 들어갈 모든 좌표를 먼저 검사한다. 검사 중에는 월드를 수정하지 않으며, 실패한 후보는 받침도 남기지 않는다. 아치와 돌출 장식의 모든 배치 열 아래 지형 중 가장 높은 곳에 높이를 맞추고 낮은 쪽에만 돌 벽돌 받침을 추가한다. 도로 중심에서 좌우 2블록, 노면 위 3블록의 통행 공간을 침범하는 후보는 제외한다.

장애물 검사는 천장 높이맵을 사용하지 않는다. 지형 계획과 일치하는 노면은 기초로 취급하되, 그 위의 구조물이나 받침 위치의 물·장애물은 덮어쓰지 않는다. 실제 세 가지 NBT를 사용해 정방향·역방향 대각선 경사로 배치를 테스트하며, 급경사·장애물·물·통행 방해의 거부도 검증한다.

8블록 반복에서는 원본 NBT의 Z=0~5 아치와 앞쪽 조각상을 사용하고, 다음 아치와 겹칠 수 있는 뒤쪽 Z=11 조각상은 런타임에서 제외한다. 원본 NBT 파일은 유지한다. 실제 NBT를 순서대로 배치한 좌표와 받침을 다음 후보의 장애물 검사에 반영하는 경사로 테스트를 수행한다.
