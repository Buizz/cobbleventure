# 공동 NPC 슬롯 설계

공동의 NPC 수용량은 조각 정의의 `markers` 중 `kind: npc_spawn`으로 정한다.
공동당 조우 한 번이라는 별도 제한은 없다. 서로 다른 조우도 아직 사용하지 않은
슬롯을 사용할 수 있으며, 공동에 여유 슬롯이 있으면 일반 통로보다 우선한다.
슬롯 하나에는 NPC 한 명만 배치한다.

- 작은 공동의 밀집은 설계자가 슬롯 수와 위치로 제한한다.
- 큰 공동은 여러 슬롯을 충분히 떨어뜨려 배치하면 여러 조우를 수용한다.
- 협동 조우 하나는 같은 공동의 슬롯 두 개를 소비한다. 네 슬롯이 유효하면
  두 쌍을 수용할 수 있다. 남은 슬롯 하나를 협동 조우 한 쌍으로 계산하지 않는다.
- `npc_placement.minimum_spacing`과 실제 전투 공간 안전 검사는 유지한다.
  겹친 슬롯이나 벽·장애물 때문에 사용할 수 없는 자리를 허용하는 정책은 아니다.
- 슬롯이 없는 공동도 지형으로 사용할 수 있다. NPC 공간 부족을 숨기기 위해
  공동 선택 자체에서 제외하지 않는다.

기본 테스트 조각의 로켓단·건물·포켓몬타워 스킨은 같은 슬롯 계약을 사용한다.

| 공동 | NPC 자리 | 로컬 좌표 (X, Y, Z) |
| --- | --- | --- |
| 1×2 (16×32) | 2 | (8, 1, 8), (8, 1, 24) |
| 2×2 (32×32) | 4 | (8, 1, 8), (24, 1, 8), (8, 1, 24), (24, 1, 24) |

조각 정의 JSON이 마커의 원본이며 NBT는 해당 자리의 바닥·머리 공간을 확보한다.
공동만 재생성하려면 `generate_dungeon_piece_skins.py`의 `--shape`를 사용하여
다른 라이브 편집 조각을 덮어쓰지 않는다.
